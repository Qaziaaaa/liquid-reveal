liquid-reveal — the package

Water on the GPU. Zero dependencies.

The hero above is the library running live — those are your images, `img.png` and a chrome-treated `helmet.png`, revealed by a real 2D wave equation integrated at 120 Hz on the GPU. Nothing else on the page is animate.

Everything visible is derived from the height field and its gradient: the refraction, the chromatic split along the wavefront, the specular glint, and the mask that wipes one image over the other. FBM noise only roughens the mask edge so the reveal reads as liquid, not geometry.

01 — how it works

Water that runs on your GPU, not on magic.

The reveal is driven by a real 2D wave-equation height field. Two framebuffers are ping-ponged on the GPU while a damped wave equation integrates at a fixed 120 Hz — so ripples propagate, interfere, and keep moving long after the cursor stops.

  1. Simulation pass. Solves the discrete wave equation u_next = u + c²·∇²u − damping on a small grid (default ~288 cells on the long axis) into a float / half-float / byte texture. Inertial properties live here: damping, viscosity, edgeAbsorb.
  2. Noise pass. Generates animated FBM noise used for organic mask edges — so the reveal boundary is never perfectly straight.
  3. Composite pass. Samples the wave height to compute a surface normal, then refracts + chromatic-aberrates the base image, gradient-maps the chrome image (like a LUT), and adds specular highlights, edge glow, bloom, vignette, scanlines and grain.

The simulation only recomputes while there is activity. A still page costs almost nothing — the loop idles to zero until your cursor touches it.

02 — quick start

Two lines of code, one full-screen effect.

The package mounts its own canvas, handles pointer input, idle drift, resize, and cleanup. You supply a container, two images, and their aspect ratio.

// 1. install
npm i liquid-reveal

// 2. markup — nothing inside is needed; the library mounts itself
<div id="hero" style="height:100vh"></div>

// 3. run it
import LiquidReveal from 'liquid-reveal';

const reveal = new LiquidReveal('#hero', {
  base:       'photo.jpg',    // shown initially
  chrome:     'chrome.png',   // revealed by the wave
  imgWidth:   1672,
  imgHeight:  941,
  focus:      [0.50, 0.44],
  exportButton: true,     // ⤓ downloads the current frame
});

No images? The bundled placeholders kick in automatically. Prefer a script tag? It also ships standalone — the page loaded above mounts the same class with no bundler.

// every running instance is on window.__ripple when demo is open
__ripple.impulse(0.5, 0.5, 0.9);   // a heavy tap in the middle
__ripple.pause();                  // freeze the frame
__ripple.setParams({ damping: 0.93 });

04 — configuration

Every tunable, grouped by what it drives.

Wave simulation (the effect)

KeyWhat it controls
waveCCourant number. CFL limit for this stencil is 0.707 — don't exceed it.
dampingPer-step decay. Lower = ripples die faster.
viscosityDiffusion term. Must stay under 0.25.
edgeAbsorb / edgeCellsAbsorbing layer that stops waves bouncing off the frame.
simLong / simHz / simMaxStepsGrid resolution, fixed sim rate, catch-up cap.
hClampSafety clamp on height.

Cursor impulse

KeyWhat it controls
impulseBase / Gain / MaxHow strongly the liquid reacts to the pointer.
impulseMinSpeedJitter dead-zone so tiny twitches don't splash.
impulseRadius / FallSqSize and falloff of the pressure bump.
splashAmpTap-to-splash strength.

Visuals

KeyWhat it controls

normalScale / specStrength / shininessThe specular glint on the surface.

Mask, gradient map, idle

KeyWhat it controls
maskHeight / maskGrad / Lo / HiHeight threshold that wipes chrome over base.

A working dial-in example — copy into the console of this page:

__ripple.setParams({
  damping:     0.96,       // longer-lasting ripples
  refraction:  0.18,       // stronger lensing
  chromatic:   0.05,       // more colour fringing
  bloom:       0.4,
  gradStops: [
    { t: 0.0, c: '#05070c' },
    { t: 0.6, c: '#1e3a5f' },
    { t: 1.0, c: '#7ec8ff' },
  ],
});

05 — recipes

Framework bindings are three lines each.

Because the instance owns its DOM, you just mount it on a ref and call destroy() on unmount. Strict-mode safe.

React

// Hero.tsx
import { useEffect, useRef } from "react";
import LiquidReveal from "liquid-reveal";

export function Hero(){
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const reveal = new LiquidReveal(ref.current!, {
      base: "/img/base.jpg", chrome: "/img/chrome.png",
      imgWidth: 4000, imgHeight: 2250,
    });
    return () => reveal.destroy();   // strict-mode / unmount safe
  }, []);
  return <div ref={ref} style={{position:"relative",width:"100%",height:"60vh"}} />;
}

Vue

<!-- Hero.vue -->
<script setup>
import { ref, onMounted, onBeforeUnmount } from "vue";
import LiquidReveal from "liquid-reveal";
const el = ref(null);
let reveal;
onMounted(() => {
  reveal = new LiquidReveal(el.value, { base: "a.jpg", chrome: "b.png", imgWidth: 1672, imgHeight: 941 });
});
onBeforeUnmount(() => reveal?.destroy());
</script>
<template><div ref="el" style="position:relative;width:100%;height:60vh" /></template>

06 — support & troubleshooting

Falls back, never fails.

WebGL1 + OES_texture_half_float, or WebGL2 + float colour buffers, on anything modern: Chrome, Edge, Firefox, Safari (macOS & iOS). If WebGL is missing or the user prefers reduced motion, a static CSS fallback panel is shown instead of a broken canvas.

FAQ

ProblemFix
Blank / invisible effectWebGL can't feed textures from file://. Serve over HTTP (any static server).
Fallback panel showsRead reveal.fellBack and reveal.errors — no GL, 404'd images, or reduced-motion.
Ripples explodewaveC exceeded the CFL limit (0.707). Lower it.
Image cropped oddlySet imgWidth/imgHeight to the real intrinsic size; tune focus.
Leaking memory in a SPACall destroy() whenever the container unmounts.
